# gygo 技术选型

网盘分享链接管理工具：录入 → 网盘解析 → TMDB 刮削 → Telegram 双向推送。

## 运行环境与部署

| 项 | 选型 | 理由 |
| --- | --- | --- |
| 部署目标 | NAS / 家庭服务器 | 无固定公网 IP，避免端口暴露 |
| 形态 | 单 Go 二进制 + Docker | 前端静态产物 `go:embed` 进二进制，零外部依赖 |

## 后端

| 模块 | 选型 | 理由 |
| --- | --- | --- |
| 语言 | Go 1.22+ | 交叉编译、单文件、资源占用低 |
| Web 框架 | Gin | 生态成熟，中间件齐全 |
| 数据库 | SQLite（`modernc.org/sqlite`，纯 Go 无 CGO） | 单文件零运维，适配 NAS |
| 数据访问 | sqlc（SQL 优先，编译期检查） | 类型安全，避免 ORM 黑盒 |
| 任务队列 | goroutine + channel + SQLite 任务表 | 无 Redis 依赖，断电可恢复 |
| 链接解析 | 插件式 `LinkParser` 接口 + 网盘适配器 | 夸克 / 阿里云盘优先，115 / 百度后续补，磁力与 ed2k 兜底 |
| TMDB | 自写薄客户端（API v3） | 从网盘分享标题与文件名正则识别片名与季集 |
| Telegram | `go-telegram/bot` | long-polling 模式，双向：收链接录入 + 推送刮削卡片 |
| 配置 | YAML + 环境变量 | 密钥走环境变量 |
| 日志 | `slog`（标准库） | 结构化输出 |

## 前端

| 模块 | 选型 | 理由 |
| --- | --- | --- |
| 框架 | Vue 3 + Vite + TypeScript | 组合式 API，构建快 |
| 样式 | Tailwind CSS v4 | 原子化，配合组件库 |
| 组件 | shadcn-vue | 组件以源码复制进项目，配色圆角动效可深度定制 |
| 视觉基调 | 清爽明亮 | 白底圆角卡片 + 海报墙，主色柔和 |
| 移动端 | 断点不破版即可 | 主场景为桌面大屏 |
| 构建集成 | `web/dist` 打包后 `go:embed` | 保持单二进制部署 |

## 关键设计决策

1. **Telegram 用 long-polling 而非 webhook**：NAS 无公网 IP，无需反向代理与端口映射。
2. **网盘解析是核心复杂度**：先实现夸克与阿里云盘两个适配器，接口统一为 `Match() / Parse()`。
3. **TMDB 识别失败不阻塞入库**：保存原始标题并标记「待确认」，Web 与 Bot 均可手动纠正后重新刮削。
4. **海报与元数据本地缓存**：图片存本地目录，避免重复请求 TMDB。
5. **状态机**：待解析 → 刮削中 → 已刮削 → 已推送 / 已失效 / 未匹配。

## 里程碑

1. M1 项目骨架 + 链接 CRUD + SQLite 存储
2. M2 夸克 / 阿里云盘解析器 + TMDB 刮削流水线
3. M3 Telegram Bot 双向 + 推送卡片
4. M4 Web 管理页（shadcn-vue）+ Docker 部署
